## 微信 CE 卡死闪退调查（18:26-18:36）
- 复现确认：不是闪退，是 ANR——滑动好友列表触发 ContactManager.getContactList → 主线程在 libwechat_alita.so 的 jniGetContactList 上等 recursive_mutex >5s，系统 ANR 强杀。
- 多个 alita native 线程同卡在该锁上（tid 6957 utm=62 在忙），属应用级锁竞争 bug（主线程直接调 native 好友列表接口）。
- speed 编译无效（非 JIT 问题）；清后台释放内存（am kill-all）后仍复现（内存 1.8GB 仅剩 210MB，但清了也卡）。
- CPU 4 核全在线，governor 不可读写（无 root）。结论：微信 CE 移植版自身缺陷，只能靠作者更新；缓解办法是冷启动后先等好友同步完再滑。

## 修复应用内转场残影
- 根因：Screen.draw 只画元素不铺满屏底色（靠 ShellView 背景兜底），转场时两层同画在 View 背景上，上层未覆盖像素透出下层旧页面 → 进入残留第一页、返回残留第二页
- 修复：MainActivity.ShellView.drawLayer 在非恒等变换时先于 s.draw 铺 Ui.BG 整屏矩形（四周 +8px 防缝），每层成为实心卡片滑动
- 录屏抽帧验证（screenrecord 12Mbps + imageio 按帧差找转场帧）进入/返回均无叠影
- 遗留观察：文件页目录加载偶发「读取中」数秒（/storage 慢或 Fs.dirSize 递归大目录），非残影问题

## 转场最终形态：圆形圆盘从右滑入
- 用户需求：保持从右滑入方向，但滑入的是圆形表盘形状的圆盘盖住主页；返回圆盘滑出
- 关键坑：clipPath 在本机硬件加速画布上圆心在屏外/部分屏外时会被忽略 → 两层无裁剪叠加（放慢动画+连拍截图确诊，非录屏撕裂）
- 解决：页面画进离屏 ARGB Bitmap（466²，复用），BitmapShader + drawCircle(cx,cy,233) 采样绘制圆盘——与 Ui.roundBitmap 同技术路线，真机验证可靠
- 进入：主页面原地，圆盘 center=CX+W*(1-p) 从右滑入；返回：center=CX+W*p 滑出。时长 300/280ms

## 圆盘转场修正：黑底与内容一起滑动（计算器风格）
- 用户反馈：之前圆盘在滑但页面元素固定原位浮现，要的是整个面板（黑底+元素）像圆形卡片一起从右滑入
- 修改：circBm.eraseColor(Ui.BG) 先铺黑底；drawCircle 前 c.translate(dx,0)，内容随圆盘平移；签名改为 drawCircled(c, s, dx)
