## WatchArcade：给圆形手表写的四个小游戏（贪吃蛇/打砖块/俄罗斯方块/跳一跳）

- 用户需求：一加手表二（刷了魔改系统）上玩常玩的小游戏，市面 APK 缺圆形表盘适配，要求本机写好再用 adb 装进去。
- 交付：`WatchArcade/` 完整 Android Studio 工程（纯 Java、零第三方依赖），APK 在 `build/WatchArcade.apk` 与 `outputs/WatchArcade.apk`。
- 圆屏适配核心：`GameView.safe` = 内切正方形半边长（R/√2 × 0.96），所有游戏内容以此为硬边界；打砖块用极坐标环形砖块 + 360° 旋转弧形挡板，是真正的圆形设计。

### 手表特性与调试坑
- 设备 OPWW234（OPPO 一加手表），466×466 圆屏，Android 11 / API 30，品牌 OPPO。
- 离腕会自动息屏，adb 操作前要 `input keyevent KEYCODE_WAKEUP`，否则截图全黑、tap 无效。
- `input tap` 在这块表上每次约 1.6s 延迟（input 每次冷启动 app_process），三击测试要把多次 tap 合并进一次 `adb shell "..."`。
- `GameActivity` exported=false，`am start` 会被拒；测试用 `monkey -p com.watcharcade -c android.intent.category.LAUNCHER 1` 起主菜单再 `input tap` 扇区。
- adb exec-out screencap -p 出 PNG 可靠；`adb pull /data/...` 会被 MSYS 路径转换坑掉。

### 修过的关键 bug
- 跳一跳闪退：Choreographer 帧回调可能先于 onSizeChanged 触发，update() 里取空平台列表越界。修法：基类加 `ready` 标志，尺寸就绪前不跑 update()。
- 三击暂停不触发：tap 窗口 1.6s 太紧 + 点别处不重置计数。放宽到 4s，且 ACTION_DOWN 落在分数区外就清零计数。
- 存档损坏要有兜底：loadState 抛 RuntimeException 就 resetGame() 重开，绝不闪退。

### Gradle 构建链路的已知阻塞（重要）
- `gradle assembleDebug`（Gradle 8.14.6 + AGP 8.13.2 + JDK 21）会失败在 `:app:compileDebugJavaWithJavac`：
  `JdkImageTransform ... jlink executable ...\PyCharm Community Edition 2025.2\jbr\bin\jlink.exe does not exist`。
  原因：PyCharm 自带 JBR 是精简运行时，不含 jlink；compileSdk 37 需要 jlink 生成 core-for-system-modules 镜像。
  后续要用 Gradle 出包时，改指向带 jlink 的完整 JDK（Android Studio 的 `E:\Android Developers\jbr` 有 jlink，但它是 JDK 25，需配 Gradle 9.x）。
- 结论：日常出包继续用 `tools/build-apk.sh`（已验证稳定，几秒出包），Gradle 只是工程完整性的备份路径。
